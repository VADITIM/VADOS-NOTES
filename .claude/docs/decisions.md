# Decisions

Reasons that would otherwise be comments. The spec's section 11 is the product-level log; this file is the code-level one.

## Core (`ios/NotesCore`)

- **Journal replay merges, it does not overwrite.** State is the synced snapshot plus every journal entry applied through the merge rules, so a newer remote edit still beats an older local one after a pull.
- **Snapshot is the last remote state, not the last local one.** A pull replaces snapshot files with remote bytes; local work lives only in the journal until a push lands.
- **Entries are removed by sequence, not "through" a sequence.** Entries for blocked pages (corrupt or newer schema on the remote) stay in the journal while the rest are removed.
- **A push only includes entries that existed when the files were built.** Building the files and capturing the sequences happen without a suspension point, so changes made during the network calls stay in the journal for the next flush.
- **409 and 422 both mean "branch moved".** GitHub answers a non-fast-forward ref update with 422; the spec's wording said 409.
- **An empty repository is started through the contents API.** The Git Data API refuses blobs on a repository with no commits, so the first commit is a README written with `PUT contents`.
- **Extent merges as the union of both axes.** Extent only ever grows, so taking the larger value per axis needs no timestamp and cannot lose an expansion.
- **Equal timestamps break ties by device name.** Keeps the element merge commutative.
- **Timestamps are rounded to milliseconds when created.** They round-trip through the file format exactly, so a decoded page equals the page that was written.
- **Points are rounded to 0.01 mm and thinned below 0.15 mm.** Same bytes on every platform, and Pencil's 240 Hz samples do not bloat the files.
- **Tool opacity is not stored per stroke.** It comes from `shared/tokens.json` by tool, so marker translucency is one definition for both renderers.

## iPad app (`ios/VadosNotes`)

- **Custom canvas, no PencilKit.** Points are the stored truth and are drawn as constant-width paths; nothing to strip out of PencilKit's pressure model.
- **Once a Pencil touch is seen, one finger pans instead of drawing.** Palm rejection without a setting. Before any Pencil touch, a finger draws.
- **A finger held still for 450 ms opens the page menu**, and the stroke it started is discarded. The Pencil never opens menus.
- **The menu opens above the finger**, so lifting without moving selects nothing; sliding onto a slot and lifting selects it.
- **Destructive slots arm on the first tap and act on the second** (V/AS confirm pattern, inside the menu).
- **Undo of an erase re-creates the stroke under a new ID.** A tombstone always wins a merge, so reviving the old ID would be undone by the next sync.
- **A new text block is journaled only once it has a character.** Abandoned empty blocks never reach the repo.
- **No blur, no glass, no shadows.** The spec overrides the Gallery's glass pill: the pop bar is a flat `panel_solid` capsule with a hairline.
- **One accent (`#FFDD1B`) app-wide.** Green, blue, red, grey and amber are taken by the spec's semantic roles, so the accent had to be a colour none of them use.
- **Swift 5 language mode in the app target.** UIKit timer and gesture callbacks would need annotations everywhere under Swift 6 strict concurrency for no gain in a single-window app.

## Windows app (`windows/`)

- **Plain ES modules, no bundler.** The frontend runs as-is in WebView2 and in any browser, so the UI can be previewed without Rust.
- **Tokens come from Rust.** `shared/tokens.json` is compiled into the binary with `include_str!` and handed to the frontend by the `tokens` command, so there is still one definition.
- **Squircles are drawn as SVG paths**, generated with the same superellipse as `Squircle.swift` (exponent 5, 12 steps per corner, extent 1.8 × radius). CSS `border-radius` would give a different corner.
- **Text is laid out once at a reference scale** (10 px per mm) and drawn at the current zoom, so line breaks do not shift while zooming.
- **Right-click opens the same menu a hold opens.** Holding still still works; right-click is the Windows habit and changes no slot.
- **Mouse draws like the Pencil; touch follows the finger rules.** Middle-drag, Space+drag and the wheel pan, Ctrl+wheel zooms.
- **The camera is not refitted on window resize.** The iPad refits on rotation; on Windows resizes are frequent and refitting would throw away the zoom.
- **Pages are written straight to files in the repository layout.** No journal yet; that arrives with Windows sync (phase 6).

### Nav, tools and paper (Windows first, iPad to follow)

- **One nav for the whole app**, the way VADOS Gallery's `BottomBar.qml` works. Each screen hands it a kind and its buttons. When the kind changes, the old buttons pop away with `back_in` over the first `state`, the new ones pop in with `back_out` over the second, and the pill's size follows across both with `power_three_in_out`.
- **The selected tool's wash slides** like Gallery's `SectionBar.qml`. The edge in the direction of travel goes first, and the trailing edge follows `nav_trail` (60 ms) later, both over `nav_slide` with `power_two_out`.
- **Holding the nav for `nav_carry_hold` (1 s) carries it.** Touch and pen pointers are implicitly captured by the pressed button; moving the capture to the nav makes the button fire a bubbling `lostpointercapture`, which must not end the carry. It retracts into a circle under the finger and follows it. On release it turns vertical if it is nearer a side edge than the top or bottom, otherwise horizontal, and expands there. The centre is stored as a share of the window, so it keeps its place on resize.
- **Tapping the selected tool opens its second nav** beside the first, on the side that faces into the window. Pen and marker get a size slider, colour presets (as many as wanted: + saves the current colour, hold or right-click arms a preset, a second tap removes it) and a colour wheel with a hex field. The eraser gets a size slider and the two modes.
- **One pen (Kugelschreiber).** The pencil left the nav; strokes made with it still render, and its tokens stay so iPad files keep drawing the same.
- **Precise erasing replaces each touched stroke with its remaining pieces**, so files stay plain strokes. The eraser sweeps a capsule from the previous pointer sample to the current one, so a fast swipe leaves no islands. Each stroke segment is cut exactly where it leaves the capsule (radius = eraser radius plus half the stroke width, so a cut end's round cap stops at the eraser's edge). Distance to a capsule is convex along a segment, so ternary search finds the closest point and bisection finds the two boundaries. Untouched parts keep their original points. The whole drag is one undo step: tombstones for the originals and new elements for the pieces.
- **Ink is smoothed, then stored.** Raw samples are resampled every `ink.sample_spacing_points` screen points, run through a Gaussian (sigma `ink.smoothing_points`, the window shrinking symmetrically at the ends so the endpoints stay put and the tip follows the pen), and simplified with Douglas-Peucker at `ink.simplify_points`. All three are in screen points, so writing zoomed in keeps finer detail. The live stroke is the same function on the same samples, so what is drawn is what is saved. Strokes render as centripetal Catmull-Rom splines through the stored points.
- **Holding still while drawing straightens the stroke.** If the pointer stays within `ink.straighten_tolerance_points` for `stroke_straighten_hold` (1 s), the stroke eases into a straight line over `stroke_straighten_snap`; moving on drags its end until release.
- **Pen and marker keep size presets** next to the slider (`width_presets` in tokens, + saves the current size, removal as for colours). The second nav and the colour panel centre on the main nav along its axis.
- **Paper is dark by default; white is a toggle** in the top bar. Neutral inks (chroma at most `neutral_ink_chroma`) are stored as they read on white paper and are inverted on dark paper. So black pen writes white on black, the file still says black, and the iPad shows it correctly.
- **Two fingers double-tapped undo; three fingers redo.** A tap counts only if the fingers stay within 14 px and lift within 320 ms; the second tap must come within 420 ms.
- **Every Windows build on `master` is published as a GitHub release** (`windows-build-N`, marked latest), so the app is a direct download.

### Folders, notes and settings

- **Notebooks are called folders and can nest.** `parent` on `notebook.json` points at the containing folder. A parent that is missing or deleted counts as top level, so a folder never disappears. Moving refuses to put a folder inside itself or one of its descendants. Deleting a folder deletes its sub-folders and notes.
- **Notes have names, colours and icons**, as optional `title`, `color` and `icon` in the page header, written in sorted-key order only when present. NotesCore decodes, merges (newer header wins, like the rest of the header) and re-encodes them, so the iPad keeps what Windows wrote even before its UI shows them. New notes are named `Note N`.
- **Moving a note creates it again in the target folder under a new page ID and tombstones the original.** The folder is part of the file path, and rewriting a file in place under another path would look like a new page with a duplicate ID to the other device.
- **Folder and note menus share four slots in two columns**: Rename, Icon & colour, Move, Delete. Delete arms first, like every destructive slot.
- **Top bars are overlays.** The title block, back button, search field and settings button each sit on the flat 85 % panel colour, so they stay readable over ink without blur (the spec rules out blur). The canvas fits the page below the bar; pan the page under it freely.
- **One settings button on every screen** holds paper colour (dark or white) and the GitHub sync fields. The top-bar sync badge was removed; sync status lives in that sheet only.
- **The text tool opens with a blinking caret only.** No pop-in and no frame. While the box is empty a drawn accent bar blinks, the height of one line; once there is text, the native caret (accent coloured) takes over and a dashed frame marks the block.

### Ordering, search and paper bounds

- **Folders and notes carry an optional integer `order`** (in `notebook.json` and the page header, sorted-key position, omitted when absent). Siblings sort by `order`; items without one take their index among their siblings sorted by ID, so old files keep their order. New items go to the end. A reorder rewrites `order` for every sibling whose index changed, which keeps the numbers small integers instead of fractions that run out of precision. NotesCore keeps the field.
- **Drag and drop on the folder screens.** With a mouse, pressing and moving more than 8 px picks a tile up; holding still for `menu_hold` opens its menu as before. With touch and pen, a hold opens the menu, and moving on from there closes it and picks the tile up, so a plain swipe still scrolls. The tile lifts as a ghost and its place stays faded. Siblings of the same kind reorder live, with a slide. Dropping on the middle of a folder moves the item into it (a note anywhere on a folder tile), and dropping on the back button moves it one level up. The window tracks the pointer during the drag, because moving the tile in the DOM drops its pointer capture.
- **The bottom nav leaves the folder screens.** "Add folder" leads the folder grid and "Add note" leads the note grid; the nav hides with a scale-out and comes back on the page.
- **Search sits in the top bar of the folder screens** and searches every folder and note name, case-insensitively, by substring. Results show folders and notes, each captioned with its folder path. Ctrl+F focuses the field; Escape clears it.
- **Ink stays on the paper.** A stroke has to start on the paper; pressing outside pans instead. On release the stroke is clipped to the paper edge (Liang-Barsky per segment), and the pieces are saved as separate strokes in one undo step. The live stroke is clipped the same way. Text boxes start and move only inside the paper.
- **The paper has rounded corners** (`page.corner_radius`, 4 mm), and the paper is the clip for guides and ink.
- **Straightened lines snap to horizontal or vertical** when within `ink.straighten_axis_snap_degrees` (7°) of the axis.
- **Undo and redo sit under the back button** on the page, not in the nav. Undo is tinted blue (navigation), redo amber, each on a 14 % wash of its colour.
- **Text has a font size and colour in the nav while typing.** The size button shows the size in points and opens a slider plus presets (8, 12, 18, 24, 36 pt). The colour button opens fixed swatches and the colour wheel. The size is remembered and used for the next text; the colour applies to the current text only, so every new text starts in the normal text colour. Nav taps do not take focus from the text box.
- **More contrast.** The ground is darker (#0E0E0E), panels lighter (#181818), borders and secondary text brighter, and the dark paper is near black (#050505) on a lighter surround (#1C1C1C).

### Paper, text and PDF notes

- **The camera stays on the paper.** Zooming out stops at the scale that shows the whole paper below the top bar; when the paper fits along an axis it is centred, otherwise its edges cannot pass the 24 px margin. Guides and cell lines are drawn inside the rounded paper clip only.
- **Cell lines (the dashed lines between cells of an expanded note) can be turned off** from the page menu, slot 9, "Cell lines off". It is a view setting like guides, shared by all notes.
- **Tapping the folder or note name in the top bar renames it.**
- **Text is Markdown.** The file stores the raw text; the canvas renders `#`–`###` headings (1.6, 1.35, 1.15×, bold), `**bold**`, `*italic*`, `` `code` ``, `~~strike~~`, `[links](url)` (underlined), `-` bullets with two-space nesting, `1.` lists, `- [ ]` / `- [x]` tasks (done ones dimmed), `>` quotes with a bar, `---` rules and fenced code blocks. The parser lives in NotesCore (`Markdown.swift`) and `windows/src/modules/markdown.js`, with the same rules. The editor shows the raw Markdown.
- **New note asks first.** "Add note" and the page menu's "New note" open a sheet with the name (prefilled `Note N`) and Blank / PDF. Choosing PDF opens the file picker; the name follows the file name unless one was typed.
- **PDF notes follow spec 7.1.** The file is stored once as `assets/<sha256>.pdf`. The note gets one A4 cell per PDF page, stacked in rows, and one `import` element per page. An A4 page is placed `original`; any other size is `fit_cell` with a 5 mm margin, centred. Pages render with pdf.js on Windows (vendored in `windows/src/vendor/pdfjs`, version 4.10.38) and PDFKit on iPad, at a power-of-two pixels-per-millimetre level for the zoom (capped at 4096 px), cached and re-rendered when the zoom needs more.
- **On dark paper a white PDF page is shown inverted.** A page counts as white when at least 80 % of its edge samples are near white. Its colours are inverted with the hue turned 180°, so colours keep their hue, and black becomes the paper colour. Only the display changes; the asset and the export stay the original.
- **Windows reads and writes assets as raw bytes** over Tauri IPC (`write_asset` with an `asset-path` header, `read_asset` returning bytes); only `assets/<64 hex>.pdf` paths are accepted.
- **Glyph paths live in `shared/tokens.json`** (`glyphs`), as SVG path data on a 24-unit grid. Windows draws them as SVG; the iPad parses the same strings (move, line, cubic, quadratic and arc commands).
- **One release for both platforms.** `build.yml` builds the Windows app and the iPad app together and publishes `build-N` with the portable exe, both installers and `VadosNotes-iPad-unsigned.ipa`. The IPA is unsigned; it installs from Windows with Sideloadly or AltStore and a free Apple ID.
- **The iPad app now matches Windows.** Shared algorithms (smoothing, straightening, axis snap, exact cutting, paper clipping, sibling order, Markdown) moved into NotesCore with tests, so both apps compute the same strokes. Tiles on the iPad use a UIKit long press: hold opens the menu, moving on picks the tile up, a pointer right-click opens the menu.

### iPad behaviour rework (2026-10-27)

Every motion value below lives in `shared/tokens.json`; the reference is VADOS GALLERY (`core/design/.../vas/Motion.kt`, V/AS `components/16`, `18`, `19`, `24`). Where GALLERY has no equivalent, the choice is marked **Assumption**.

- **Tiles open on a tap.** The secondary-click recogniser on each tile also fired on finger taps, so a tap opened the haptic menu; it now only accepts the pointer. **Folders rename in place** by tapping their name in the top-left pill, as a note does; the haptic menu keeps Rename too.
- **The app is edge to edge.** The root ignores the safe area and hands the real insets down as `screenInsets`; the top bar, sheets, undo/redo and the nav pad themselves by them. The dark bands were the ground showing through the safe-area margins around a canvas that stopped at them. The launch colour now matches the ground (`#0E0E0E`), and the status bar is light content over the app.
- **The page fits centred.** The fit reserves the top bar's height at both ends and shows the whole note, every column and row, centred (`CanvasCamera.fitting` uses the zoom floor). It used to fit only the first cell, so a large note opened on its top left corner.
- **The camera may travel `panSlackShare` (45 %) of the screen past the paper on each axis.** Before, a fitting page was locked in the centre and a larger one could not pass the margin.
- **A finger pans; the Pencil draws.** With pen, marker and eraser, a one-finger drag pans everywhere and a finger hold still opens the page menu. Two-finger pan, pinch and the undo/redo taps are unchanged. **Assumption:** the lasso draws with the finger as well as the Pencil, since selecting is not inking and a finger-only user must still be able to select.
- **Name prompts sit at the top**, `insets.top + 24` below the edge, so the keyboard never covers them. **Settings drops in from above the top edge** (`move(edge: .top)` over `sheet_drop`, 420 ms, `back_out`) and leaves the same way in reverse (`back_in`, the time-reversed `back_out`). Sheets now close in two steps (the content leaves, then the host goes), so every sheet's leave animation plays. **Assumption:** 420 ms has no GALLERY equivalent; `overlay_enter` read as too fast.
- **Back sits directly left of settings on every screen**, in the top bar's control cluster; it pops in and out (GALLERY `TOP_ENTER` / `TOP_EXIT`) as the folder depth changes.
- **The note's created date is read from its page ID.** IDs start with ten base-32 characters of creation milliseconds, so `Identifier.creationDate(of:)` decodes them and no schema field was added. It shows as `DD/MM/YY` in 12 pt mono next to the title. **Assumption:** only the canvas top bar shows it.
- **The note name edits in place.** Tapping the title swaps the sweep title for a field in the same face, focused with the accent caret; every keystroke renames the note, and an emptied name falls back to `Note N`. **Assumption:** while editing, the name shows in the case it is typed rather than upper case.

#### Nav

- **The nav is back to its original size** (`NavMetrics.scale` 1). The 1.7× enlargement was reverted on request.
- **There are no undo and redo buttons on the page.** Undo and redo are the two- and three-finger taps and Cmd+Z / Cmd+Shift+Z.
- **Carrying the nav keeps its shape.** It no longer retracts into a circle: it lifts to `scales.held` (1.05, GALLERY `HELD_SCALE`) with an accent outline and follows the finger from the point it was grabbed. The secondary nav and colour panel pop out while it is carried and pop back in where it lands. Orientation still turns vertical near a side edge. *Superseded 2026-11-03 by "Carrying the nav: grabber, bubble, corner park, edge lock".*
- **Only the two grips at the ends carry the nav**, after `navigation_grip_hold` (150 ms, GALLERY `DRAG_REST_MS`: a finger resting that long is picking something up). Holding a tool for `menu_hold` lifts it and drags it along the nav; it swaps with a neighbour once it passes half the neighbour's extent, with a segment tick, and the order is stored. The nav keeps its layout order while dragging and moves the neighbours by offsets only; on release the order is committed without animation and the lifted tool glides the remaining distance into its slot. Moving the layout during the drag made the lifted tool jump back to its old slot and spring forward. In the secondary nav the same hold lifts the whole group between dividers and reorders the groups for that tool. **Assumption:** a held colour or size preset still arms for removal as before; the group lift runs alongside it. *Superseded 2026-11-03 by "Carrying the nav: grabber, bubble, corner park, edge lock".*
- **The navs avoid other UI.** The top bar's title and controls and the undo/redo cluster report their frames (`ChromeFramesKey`); the keyboard reports its height. If the nav overlaps any of them it moves to the nearest free spot found by stepping clear of each obstacle in four directions (three passes), so the keyboard pushes it straight up. The secondary nav and panel are placed beside it the same way, with the nav itself as one more obstacle. Moves use `springs.placement`. **Carrying the nav keeps its secondary nav and panel open**; they follow it without the placement spring. **The nav stays where it was picked up**: the grab offset is taken from the first drag sample. The long press reported its end before any drag sample, and the offset used to be taken from that empty sample, so the nav jumped to centre on the finger.
- **Springs.** GALLERY glides items with Compose's default `spring()` (damping 1, stiffness 1500), which is `springs.placement` (response 0.162 s, damping 1). **Assumption:** the active-tool wash uses a bouncier `springs.wash` (response 0.34 s, damping 0.55) and the secondary nav's selection ring a slightly bouncy `springs.selection` (0.3 s, 0.72); GALLERY slides its highlight on a 240 ms tween instead.
- **The press pops.** A plain button scales up to `scales.press_pop` (1.08) over `press` (80 ms, `power_two_out`) and pops back over `release` (220 ms, `back_out`). **Anything that can be held** (tiles and buttons with a hold action; not the nav, which shows no hold indicator) grows slowly to `scales.hold_grow` (1.05) over the whole `menu_hold`, linear, and at the hold threshold pops to `scales.hold_pop` (1.12) on `back_out` over `state`, together with the hold haptic (`HoldPop`). **Assumption:** 1.05 and 1.12 have no GALLERY equivalent; 1.05 matches `HELD_SCALE`.

#### Secondary nav

- **It opens like GALLERY's viewer date pill** (`TypedDatePill`), at about double its first speed: the panel pops in as a circle from its own centre (`back_out`, half of `state`) and widens from that centre to both ends (`power_three_in_out`, `state`, starting a quarter of `state` in). Every element (each preset, button, swatch and divider, not each group) pops in with its own quarter turn (`back_out`, `state`) at a random start within the first half of the 440 ms timeline (`ElementReveal`). **Closing runs it back**: the elements turn and pop out at random starts within the first 110 ms (`back_in`, `state`), the panel narrows to a circle, and the circle pops away over half of `state`. **Assumption:** "half the total time" means the start window is half of the two-`state` timeline. The scale used to run around the nav layer's corner, because the transition sat outside the positioned view; each stage is now scaled inside the panel's own frame. **Interacting with the canvas no longer closes it**; only the tool, its "…" or a new text session does.
- **Switching tools morphs it.** Groups carry stable IDs per tool, so the old ones pop out, the new ones pop in after them (GALLERY `TOP_POP_OUT` then `TOP_POP_IN`), and the panel's size follows over `state × 2` on `power_three_in_out`, as GALLERY's pill does.
- **There is no size slider in the secondary nav**; it keeps the size presets, each with its size in px under it (millimetres ÷ 0.35278, one decimal under 10), and the plus that saves the current size. **Sliding along the nav sets the selected tool's size**: a quick drag of 6 pt anywhere on the nav (well before the `menu_hold` that lifts a tool or the grip hold that carries it) sizes the selected pen, marker or eraser, or the text size while typing. The nav's items leave first (`power_two_in`, `press`), then the slider pops in from `scales.slider_enter` (0.94, `back_out`, `overlay_leave`); the nav becomes a slider of its own length with the size in px beside the knob. **Assumption:** 0.94 has no GALLERY equivalent; it keeps the pop subtle. With the text or lasso selected a drag does nothing. The drag moves the size relatively from where it was, on the same logarithmic scale as before: left to right small to big in a horizontal nav, bottom to top small to big in a vertical one. **Assumption:** the text size item slides the font size the same way.
- **Swatches and size presets sit on a 34-unit pitch** instead of 40, with no gap between them.
- **The selection ring travels.** One ring per group is a matched geometry element; picking another swatch, size or mode moves it there on `springs.selection`.
- **"…" opens a secondary nav**: Delete note, Import | Add column, Add row | Guides, Cell lines. Delete arms first (a second tap within 2.4 s deletes), like every destructive slot. Import stays disabled until importing into a note exists. Previous note, next note, new note and fit page are gone. The canvas hold menu keeps the remaining page actions as a vertical list.

#### Text and lasso

- **Finger or Pencil adds text.** A tap on the paper with the text tool starts a text box; a finger drag there still pans.
- **The text being edited has handles**, set 22 pt out from the text so they never cover it. Dragging the left or right accent handle resizes its width (at least 20 mm, kept on the paper); dragging the box moves it. Both write the session's box live (`placeText`), and finishing records one undo step that includes the box.
- **A tap on text edits it; moving it needs `text_move_hold` (600 ms).** Moving the finger before then pans (finger) or does nothing (Pencil), so taps never nudge text. **Assumption:** 600 ms, longer than `menu_hold`, because a longer hold than the menu's was asked for.
- **While text is edited, the nav shows Edit** (keyboard glyph), which brings the keyboard back if it was dismissed.
- **Lasso.** The loop is drawn dashed in the accent. On release every element the loop touches is selected (`Lasso.touches`): a stroke with any point inside or any segment crossing the loop, text or an import whose rectangle overlaps it. Requiring most of an element inside made selection unreliable. Dragging inside the selection's dashed bounds moves everything by one offset, drawn live through `RenderOptions.elementOffsets`, and commits as one undo step (`Library.moveElements`). The selection survives a tool change and clears when a finger presses the canvas outside it; a finger inside it moves it with any tool, the Pencil only with the lasso.

#### Folders and transitions

- **Groups work like GALLERY's album groups**: folders and notes can each be gathered into named groups inside a folder (`Add to group` in the item's menu; the group's own menu renames or ungroups). A group lies as a leaning stack of its cards (tilt 7°, shift 9, shrink 0.05, darken 0.2, three layers) beside its name; tapping or swiping right opens it into rows of three under a heading, swiping left or tapping the arrow folds it back. One linear clock of `stack` (360 ms), each card eased on its own, the stagger spread over `shares.stack_stagger` (0.35); opening lands on `back_out`, closing on `power_three_in_out`; the arrow travels and turns over the middle half; the shut name is cut from its left end in step. A swipe drives the same clock, decides at 0.3 and finishes only the share left. **Assumption:** groups are stored on the device (`groups.<folder>` in user defaults), as GALLERY keeps its groups in its settings rather than on disk, so no schema change was needed; grouped items are not dragged.
- **The haptic menu is a vertical list next to the finger.** Its top left corner sits 14 pt right of the touch point at the touch height; with no room on the right its top right corner sits left of it, with no room below it opens upwards, and it is clamped to the screen. It is 196 pt wide with 46 pt rows: an icon and the action, in sections split by thin dividers (Rename, Icon | Add to group, Move | Delete; Add column, Add row | Guides, Cell lines | Delete), and the destructive action always last. The panel used to be placed with an offset, so its scale-in ran from the screen corner; it is now placed by alignment guides and scales out of its own corner on `back_out` over `overlay_enter`; the rows pop in after `rise_delay` (80 ms), `rise_stagger` (40 ms) apart (GALLERY `RISE_DELAY_MS`, `RISE_STAGGER_MS`). It leaves on `back_in` over `overlay_leave`.
- **Folder to folder keeps the chrome.** Both folder routes share one screen identity, so the top bar, search, back and settings stay put and only the contents (keyed by folder) cut with GALLERY's folder transition: in from `scales.folder_enter` (0.96) after the 60 ms gate over `section_enter`, out as a 120 ms fade.
- **Opening a note flies out of its tile** (GALLERY's viewer flight, V/AS `components/16`): one progress over `viewer_enter` (280 ms, `power_two_out`), the canvas scaled from covering the tile to the screen while a rounded mask grows from the tile's frame, its corner going from 18 to 24 and gone over the last `flight_corner_fade` (30 %). The top bar, nav and undo/redo pop in once the flight is `chrome_arrival` (85 %) done, `chrome_stagger` (45 ms) apart. **Assumption:** closing a note still cuts back to the folder; shrinking back into the tile was not asked for.
- **Naming.** The new identifiers spell out "navigation"; the existing `Nav…` names (`ToolNav`, `NavItem`, `subNavKey`) were left as they are, since renaming them is a refactor nobody asked for.

#### Folder screen and canvas fixes (2026-10-27, second pass)

- **Folder tiles show their icon in the centre of the canvas area**, as the Add folder tile does, and their colour as the tile outline; the icon beside the name is gone.
- **Notes lie in a masonry grid**: columns of at least 170 pt, each note spanning as many grid columns as it has page columns and as tall as its pages, placed in the lowest free spot. #### Text on the guide rows (2026-10-30)

- **The row gap is the guides' own row spacing.** `g = cell_height / round(cell_height / grid_spacing)` = 297 / 59 = 5.034 mm (`PaperGeometry.rowSpacing`, which `drawGuides` now reads too), so the rhythm keeps its phase across vertically joined cells. There is no row-gap preference (grid spacing is fixed at 5 mm), and zoom scales page millimetres as a whole. Everything below is computed from `rowSpacing` and the font, never stored, so a future preference or page type would carry through.
- **Normal text size is the size whose line is exactly one row.** `s = g / (ascender − descender + leading)`, with the metrics read from the face at 1 pt (`UIFont`, linear in size). Space Mono has 1.120 + 0.361 + 0 em, so `s` = 3.399 mm. Every line gets `minimumLineHeight = maximumLineHeight = k · g`, with `k = ceil(scale)` rows: 1 for paragraphs, lists, quotes and code, 2 for the three heading levels (×1.6, ×1.35, ×1.15) until phase 2 gives headings their own sizes. A block's height is its line count × `k · g`, replacing the old `ceil` of the measured height, which added up to 1 mm per block in page units. The `line_height` token (1.35) is no longer used by iPad text: the row is the line height. Windows still uses it.
- **Baselines sit on guide lines.** A line's target baseline is `a · s + (k − 1) · g` below its top (`a` = ascender), so a heading's baseline sits where a normal line in its last row would. TextKit's own baseline for that font and line height is measured once with an `NSLayoutManager`, and the difference is set as `baselineOffset` on every run, so the result does not depend on where TextKit puts extra space or leading. A text box's top is snapped to `round((y + a · s) / g) · g − a · s` (inside the paper), which puts the first baseline on a guide and every later one `g` below it, wrapped lines included.
- **One size, no size control.** The font-size item, its slider and its presets are gone from the typing nav, and the text tool has no secondary nav (asked and confirmed). The `font_size_range`/`font_size_presets` tokens stay for Windows.
- **Old blocks: drawn fitted, rewritten on edit** (asked and confirmed). The renderer ignores a stored `font_size` and draws at `s` from the snapped top. Opening a block to edit it, dragging it, or moving or scaling it with the lasso writes `font_size = s` and the snapped box, so Windows sees the same numbers after sync. No schema change.
- **The editor lays out like the renderer.** The text view uses TextKit 1 (`usingTextLayoutManager: false`), the same layout system as the measurement and string drawing, with the same fixed line height and offset at its zoom. After every change outside a marked (IME) range the whole storage is restyled from each character's Markdown style (phase 2), so pasted rich text cannot bring its own font or spacing.

Underline is `<u>…</u>` and dashed underline `<u class="dashed">…</u>` (asked and confirmed): GitHub shows both as an underline, and only the dashed look is ours. - **The parser learned three things.** Underline tags (nested tags close innermost first; `<` is now escapable), the link's target (kept in `MarkdownStyle.linkTarget`, so an edited link is written back intact), and closing before opening: at `***` after `*a`, the open italic closes before a bold opens, where the old parser opened a bold and swallowed the rest of the line.
- **The editor shows styles, not markers** (asked and confirmed). `RichText.lines` turns Markdown into one run list per line, and `RichText.markdown` turns them back after every committed change. Inline markers are hidden and become a `MarkdownStyle` on each character (the `.markdownStyle` attribute), which the editor draws with the renderer's own run attributes. Line syntax (`# `, `- `, `1. `, `> `) stays as visible, dimmed characters, so the caret, selection and delete treat it as ordinary text and typing `# ` makes a heading. Fenced code and rules are shown and kept verbatim. Marked (IME) text is committed only when composition ends.
- **Writing Markdown back is canonical and checked.** Marks open in one order (link, underline, strike, bold, italic) and the writer closes back to the longest shared prefix, so tags always nest. Emphasis cannot start or end on a space in Markdown, so edge spaces of a bold, italic or strike span move outside its markers (underline keeps them). Text is written without escapes first. If parsing that back does not give the same runs, the line is written again with every markup character escaped, so a literal `*` never turns into emphasis and an existing note is not filled with backslashes.
- **The .md button.** While text is edited the typing nav leads with `.md`. It opens the `text-style` secondary nav through the same `toggleSubNav` switch as the colour nav. It has two groups: bold, italic, underline, strikethrough, dashed underline and inline code, then heading, bullet list and numbered list. A style shows as selected when every character of the selection has it, or when the caret's typing style has it. A line style shows as selected when the caret's line is that kind. Underline and dashed underline exclude each other.
- **Applying.** With a selection, a style is added to all of it, or removed if all of it already has it. With only a caret, the style becomes the typing style until the caret moves. Line styles act on every line the selection touches; pressing the current kind again removes its prefix, and numbered lines count from 1.
- **Headings take whole rows.** Heading scales are now 2, 1.5 and 1 (were 1.6, 1.35, 1.15), so level 1 and 2 take two rows and level 3 one bold row. The font is scaled and its baseline still lands on a guide (phase 1's offset), so the rows below keep the rhythm. Levels 4 to 6 render as level 3.
- **Known limits.** A line that only looked like a heading because its `#` was escaped becomes a heading once it is edited, because the editor shows that `#` as text. Windows still renders `<u>` tags as literal text until its Markdown module is ported.

#### Code spans and blocks (2026-10-30)

- **Stored in the same Markdown.** A code block is a fenced block with the language as its info string (```` ```javascript ````), the standard form. Inline code with a language is `` `code`{.javascript} ``, Pandoc's attribute syntax: Markdown has no other way to tag an inline span, and the code text stays literal (no HTML escaping). Plain `` `code` `` (no language) still works, and the `.md` nav's code toggle makes it. Identifiers are `javascript`, `csharp`, `java`, `python`; reading also accepts `js`, `cs`, `c#` and `py`. An unknown `{.x}` stays literal text, and `{` is now escapable, so prose that starts with `{.` after a code span is written as `\{`. No schema change.
- **The code button.** While text is edited the typing nav has a `code` item beside `.md`. It opens the `text-code` secondary nav with JS, C#, JAVA, PY and "Aa" (normal text) in one selection ring, through the same switch as the other secondary navs. The ring shows the language of the selection, the caret's code span or the caret's code block, or "Aa" when none is code.
- **What a language does.**
  - **Selection within one line:** it becomes a code span in that language.
  - **Caret only:** it becomes the typing style; inside an existing span it changes the whole span.
  - **Selection across lines:** the lines are wrapped in a fence of that language.
  - **Inside a block:** a language rewrites the block's fence.
  - **"Aa":** removes the code style from the selection or the caret's whole span. Inside a block it removes both fences, so the lines become ordinary text, and their markup characters are escaped when saved.
- **Boundaries are ordinary text.** In the editor a span is only a style on its characters, so the caret, selection and delete move across prose and code like any style change. Typing at a span's end continues the span (the character before the caret sets the typing style, as with bold).
- **On the rows.** A span is the body font at the body size with a background, so prose and code share a row. Block lines and their fences are one row each in the editor. On the canvas the fences are hidden, so the code lines move up two rows but stay on the guides.
- **Highlighting.** `SyntaxHighlighter` (NotesCore, `SyntaxHighlighter.swift`) is a small scanner per language: keywords, strings, numbers and comments. It covers line and block comments, template and triple-quoted strings across lines, escapes, and digits inside identifiers not being numbers. A block is scanned as one text, so a comment or string can span its lines. A span is scanned on its own. Plain code keeps the block's ink colour. The highlight colours and the code background are tokens per paper style (`syntax.dark`, `syntax.light`), VS Code-like hues, and the background replaces the old 14 % ink tint.

#### Library grid, drag and groups (2026-10-30)

- **Folders come first on every level.** The folder section is always above the notes, also when a folder has no notes yet. Before, a folder without notes showed its notes section (with the add tiles) above its subfolders.
- **Why the drag hunted.** The drop place was found by testing the finger against the tiles' current frames and putting the dragged tile before or after the tile under it, split at that tile's middle. Every reorder moved those frames, so the next sample hit a different tile and the order jumped again. Notes are packed into the shortest masonry column, so "before tile X" often landed far from X when the sizes differ. Release then committed whatever the last jump had produced. On pickup the ghost also played the tile entrance (faded, 14 pt low, 0.94) and grew around its centre, so the grabbed point slid off the finger.
- **The slot under the finger.** For every possible insertion index the layout of the other tiles plus the dragged one is computed with the same `MasonryLayout` the grid uses, and the index whose slot holds the finger wins; the nearest slot wins when the finger is in a gap. The current index is kept while its slot still holds the finger. This depends only on the other tiles' order, not on the live arrangement, so it cannot hunt. Release commits exactly the order on screen. The folder grid is a `MasonryLayout` of single cells now (same 230 pt minimum column and tile height), so both sections share the computation.
- **The ghost stays on the grabbed point.** It appears without the tile entrance and lifts to `scales.held` around the grabbed point.
- **Dragging into and out of groups, folders and notes alike.** Cards of an open group can be lifted like grid tiles. Dropping a tile on a group of its kind (open or shut) adds it to that group; the group shows an accent outline while it is the target. Dragging a card out of its group puts it in the grid live at the slot under the finger, and dropping there takes it out of the group at that place. Dropping a card on a folder or the back button also takes it out of its group. **Assumption:** the prompt asked for folders "the same way notes can", but nothing could be dragged into or out of a group before, so both kinds got it. Groups stay in `Preferences`, no schema change.
- **Closing an open group.** A tap on any empty space of the folder screen (the gaps of the group's own row included) and a sideways swipe that starts outside every open group close the open groups. **Assumption:** "swipe back" is read as either sideways direction, since a swipe outside a group had no meaning before.

### Windows and Linux parity (2026-10-28)

The Tauri app was rebuilt from the iPad app, so every behaviour pass above applies to Windows and Linux too. Only the platform mappings are new.

- **Input mapping.** Pen and mouse act as the Pencil; touch acts as the finger. A pen's eraser end (`buttons & 32`) stands in for the Pencil double-tap's "switch to eraser": it erases while it touches and the tool returns on lift. Right-click opens whatever a hold opens. Wheel, Shift+wheel, Ctrl+wheel, middle-drag and Space+drag keep their earlier Windows meanings.
- **Clean taps on touch.** Two- and three-finger undo and redo count when every finger stays within 10 px and the whole touch ends within `undo_tap`, as on the iPad. Pointer events have no gesture recognisers, so the canvas tracks the touch sequence itself.
- **Springs are `linear()` easings.** Each `motion.springs` token is integrated once (stiffness `(2π / response)²`, damping `4π · fraction / response`) and sampled into a CSS `linear()` curve, so the Web Animations API plays the same spring SwiftUI does. The nav's position spring is integrated per frame instead, because it is retargeted while it moves.
- **Pops turn in CSS.** `RotatePop` is `perspective(2 × size) rotateY(-90°) scale(0.001)` with opacity, on `power_two_out` / `power_two_in`. Matched-geometry rings, washes and the variations mark are single elements that FLIP between targets on their spring.
- **The camera refits on resize,** as the iPad refits on rotation. This replaces the earlier Windows choice to keep the zoom on resize.
- **Naming sheets rise after `keyboard × 2`** unless the Virtual Keyboard API reports a touch keyboard, whose height they ride on.
- **Sync follows the iPad's protocol with a dirty-path set instead of a journal.** Local files are the merged state; `synced/` keeps the last remote bytes and `sync-state.json` the head, blob SHAs and blocked paths. Every local change marks its file path dirty with a counter. A pull merges each changed remote file into the local one with the same rules (element last-writer-wins with tombstones, header last-writer-wins, extent union), which gives the same result as replaying a journal over the new snapshot. A push sends dirty files whose bytes differ from the snapshot, then clears only paths whose counter did not move during the network calls. 409 and 422 back off and retry with `sync.backoff_seconds`. A store that has never synced counts every local file as dirty, so notes made before sync was set up are pushed.
- **The token lives in Credential Manager** (keyring crate; Secret Service on Linux, Keychain on macOS) under service `com.vaditim.notes.github`, account `token`, like the iPad Keychain item.
- **Export renders a raster PDF.** The page is drawn at up to 4 px per point (capped at 48 MP), encoded as JPEG and wrapped in a one-page PDF at the paper's size in points, then saved through a save dialog. The iPad exports vector PDF.
- **The ASCII art is compiled in from the iPad resource** (`include_str!` of `ios/VadosNotes/Resources/background.txt`), so there is one copy. The pattern is a rotated background image drifted by a Web Animation, the same tile, stagger and speed as the iPad's Core Animation drift.
- **Linux builds in the same workflow** (`linux` job: AppImage and deb) and ships in the same release.

### Code indentation (2026-11-02)

- **Inside a fenced code block, typing follows the code.** Enter keeps the line's indent, adds one level after an unclosed `{`, `(` or `[` (and after a trailing `:` in Python), and drops one level after a Python `return`, `pass`, `break`, `continue` or `raise`. Enter between a bracket pair splits it around an indented empty line with the caret on it. Typing `}`, `)` or `]` on a blank line takes one level off. Backspace in the indent removes one level, and Tab (hardware keyboard) runs to the next stop. Brackets inside strings and comments are ignored, using the syntax highlighter's tokens. Spaces after the caret are swallowed by Enter.
- **The level is read from the block.** The smallest indent already in the block (2 to 8 spaces) is the unit; an unindented block uses 4. **Assumption:** no per-language style default (JavaScript 2, the others 4); the block decides, so pasted code keeps its own style.
- **One rule set, two copies.** `NotesCore/CodeIndentation.swift` (tested) and `windows/src/modules/codeIndentation.js` (the same cases, checked with real key presses in a browser). Inline code spans are left alone; they cannot hold a line break.
- **The keyboard turns into a code keyboard.** On the iPad, while the caret is in code, autocorrection, auto-capitals, smart quotes, smart dashes and spell checking are off, so `"` stays `"`.
- **Edits go through the platform's undo.** The iPad replaces through `UITextInput`, Windows through `execCommand("insertText")`, so each auto-indent is one undo step. On Windows the closing bracket is handled on `beforeinput`, not `keydown`, because AltGr layouts (German `}` is AltGr+0) report Ctrl+Alt on the key event.

### Asset sync (2026-11-02)

- **Repository and local names.** In the repository an asset is `assets/<sha256>` with no extension (spec 4.4). On the devices it stays `assets/<sha256>.pdf` beside the store, as both clients already wrote it, so nothing is moved. `RepositoryPath.asset` and `repositoryAssetPath` accept only `sha256:` followed by 64 lowercase hex characters, so an asset name from a remote page can never reach outside the folder.
- **Uploads follow the pages, not a journal entry of their own.** Each push adds every asset that a live import element on a live page references, that the device holds and that the remote tree lacks. The asset lands in the same atomic commit as the page that first carries it (blobs are created in path order, so `assets/` is written before `notebooks/`). The page's journal entries on the iPad and its dirty path on Windows keep an offline import pending until that commit lands, which is how "asset uploads go through the journal" holds. **Assumption:** deriving uploads from the pages also uploads the assets of pages pushed before this change, which a separate journal entry would have missed; and there is no new `Change` case for older journals to misread.
- **Downloads.** After the push, each referenced asset that the device lacks and whose blob the remote tree lists is downloaded, hashed and kept only if the hash matches its name; a mismatch is skipped and tried again next sync. The canvas forgets its cached failure for those assets (`ImportImages.reload`, `reloadAssets`), so the grey placeholders fill in without reopening the note.
- **Listing assets once.** A pull with an unchanged head used to return at once, so a store that synced before assets did would never learn their blob SHAs. The sync state carries `assetsListed` on both clients; while it is unset, the next pull lists the tree once even if the head did not move. Asset blobs are recorded in the state but never copied into `synced/`.
- **50 MB cap.** GitHub warns above 50 MB and refuses files over 100 MB, and a Git Data API blob is sent as base64 in JSON, a third larger again (about 67 MB for 50 MB). Worksheets and scanned handouts are a few MB, so 50 MB leaves room for long scans while staying clear of both limits. It lives in `shared/tokens.json` (`sync.asset_limit_megabytes`). Imports above it are refused with "Larger than 50 MB"; the synchronizer also skips any local asset above it rather than failing the commit. Git LFS stays the fallback (spec 7.3).
- **One hash in NotesCore.** CryptoKit is not available on Windows and Linux, so `ContentHash` is a plain Swift SHA-256, tested against the standard vectors. The iPad import now goes through `AssetStore.add`, which hashes, deduplicates and writes in one place; Windows hashes with Web Crypto.

### Imports as pages, installed fonts, code pairing, merged markers (2026-11-02)

- **Imports fill the cell.** The drawn rectangle of an import is the whole cell its placement centre lies in, computed at draw time on both clients (`importRect`, `PageRenderer.importRect`). - **Markers never stack.** All marker strokes on a page are drawn opaque into one layer, and the layer is composited at the marker opacity (an offscreen canvas on Windows, a transparency layer or an alpha view on the iPad). Where two markers cross, the later colour covers the earlier instead of darkening. The live stroke is drawn into the same layer (Windows redraws the page while a marker is down; the iPad's live marker path is a sublayer of the marker view), so the overlap never shows while drawing either.
- **Long strokes.** No code splits a stroke: a stroke is cut only where it leaves the paper. What showed as segments was translucent marker strokes overlapping at their joins, which the merged layer removes. Pen strokes are opaque and were never affected.

When the picked font has a readable file outside `/System`, it is also copied into the app's own font folder so it survives relaunches regardless of the grant.
- **Note module.** Import, Export, Rename and Delete note moved out of the ASCII column into a Note module in a 2 × 2 grid; GitHub sync and Note split the bottom row evenly, so sync is about half as wide as before.
- **Transfer view.** `transfer` is a new full-screen sheet (`SheetRequest.transfer` on iPad, `kind: "transfer"` on Windows and Linux), opened from the Note module, and switching from settings to it fades the content instead of replaying the drop. Each cell is drawn on its own (`renderCell`, `PageRenderer.cellThumbnail`). Selection order is reading order, not tap order, so the numbers always read left to right, top to bottom, the same order the export pages and import placements follow. Dragging paints: the first cell decides whether the drag selects or clears. In Import the selection is capped at the PDF's page count, the grid adds `ceil(pages / columns)` empty rows (dashed), and the default places the pages in those rows; the preview draws the PDF pages in their target cells before anything is written. `placeDocument` writes one import element per selected cell and grows the extent to cover the furthest one.
- **Multi-page export.** Export is one A4 PDF page per selected cell (Windows and Linux: one JPEG per page in a hand-written PDF; iPad: `UIGraphicsPDFRenderer`, vector). The whole-note single-page export is gone.
- **PDF render scale (Windows and Linux).** Import pages were rendered at `level / millimetresPerPoint` pixels per point instead of `level * millimetresPerPoint`, about 64 times the pixels intended. Two such pages filled the 192 MB image cache, so each render evicted the other and the page flickered between the two forever. Fixed; the iPad was already correct.
- **Slab button titles (Windows and Linux).** The title was a bare text node, which the squircle SVG covered, so slab buttons showed no label. It is now a span (`slab-button-title`) above the shape, with `setTitle` for updates.

### Transfer pages, bundled handwriting font, single-cell growth (2026-11-02)

- **Pages carry their page number, not reading order.** A placement is a cell plus a page index (`PagePlacement` on iPad, `{ column, row, index }` on Windows and Linux). Painting starts only from an empty cell, and a tap on a placed cell clears it. (It first needed a `tile_drag_hold` hold, which a moving finger or mouse kept cancelling; carrying is now immediate.) On the iPad the strip pages still need the hold, because the sheet scrolls under them. Pages in the strip can be held and dropped on a cell too: in Import that places that PDF page there (an unplaced page replaces what the cell held); in Export a strip page dropped on another strip page swaps their order.
- **The PDF strip.** The left column shows the PDF top to bottom: in Import the source pages (placed ones lit, the rest dimmed), in Export the pages of the PDF about to be written, in order.
- **Top row.** Export/Import, Normal/Inverted and the confirm button sit in one row at the top; All, None and the "Each number…" caption are gone (row numbers still select a row).

- **Copy colour.** Every colour wheel panel has a Copy button at its top right that writes the current hex to the clipboard and reads COPIED for 1.4 s.

### Nav that never dies, synced PDF inversion, growing from View All (2026-11-03)

- **Nav gestures recover from cancellation.** The nav's drags (edge hide, collapse swipe, size slide, tool and group reorder, carry) set `swallowUntil = .distantFuture` when they start and only cleared it in `onEnded`. SwiftUI does not call `onEnded` for a cancelled gesture: a file picker or sheet presenting, a view identity change, or the canvas taking the touch left the swallow in place for good, so every tap on the main nav, the secondary nav and the wheel button was dropped. This happened most after a PDF import, which presents the system picker and re-renders the page while it loads. Each gesture now also drives a `@GestureState`, which SwiftUI resets on end and on cancel; when none is active, `recoverGestures` clears whatever a missed `onEnded` left (swallow, sizing, reorder, carry, edge drag). The same reset covers the size slider's held state and the colour wheel's drag. `PillMotion.enter` and `leave` also clear `isMutating`, which an interrupted mutate could leave set.
- **PDF inversion is stored per page element, not per device.** The device preference `invertsPdfPages` let the iPad and the desktop show the same note differently, so it is gone. `inverted` on an import element decides the look on every device, whatever its paper. A new import sets it from one white-page sample of the source page and the importing device's paper; the sample is drawn over white, so a transparent PDF reads the same in PDFKit and pdf.js. Elements imported before have no field and keep the old rule (dark paper and a white page) until set once. View All's Normal / Inverted writes the flag on every PDF page of the note in one undo step, and on a PDF waiting to be imported; the page menu's Invert PDF / Original PDF writes it on the page under the finger. The iPad renders every PDF page over opaque white and darkens a page that is not white on a background queue the first time it is asked for inverted.
- **View All grows the note.** In View all, a dashed + strip runs down the right of the grid (Add column) and along its bottom (Add row), only for an editable note. Each adds one cell through the same `expand` as the page menu.

### Palm guard on the iPad canvas (2026-11-03)

- **A resting hand never moves the canvas.** `PalmGuard` (iPad only, `Canvas/PalmGuard.swift`) classifies every finger touch. A touch is a palm when its `majorRadius` reaches 52 pt (it was 30, which an ordinary fingertip reports, since iPad radii come in steps of about 10.4 pt: 20.8, 31.3, 41.7; with 30 most one-finger pans were cancelled as palms), when the Pencil is on the glass, or when it starts in the rest zone within 1.2 s of the Pencil's last contact. The rest zone is the bottom quarter of the canvas plus the right 35 % of its lower 55 %, and it widens (by 64 pt) around where large contacts actually landed, up to the last 24 of them, so it follows the user's hand.
- **How palms are kept out.** A passive `PalmWatchGestureRecognizer` sees every touch without claiming it. Pinch, two-finger pan and the undo and redo taps refuse palm touches in `shouldReceive`; the pinch and pan subclasses cancel themselves when one of their touches grows into a palm, and a cancelled camera gesture restores the camera it started from. The one-finger pan and the hold menu skip palms, a finger pan that turns into a palm snaps back, and a Pencil landing during a finger pan cancels it and starts writing. A palm that lands first no longer takes the canvas's single active touch away from the Pencil. Pencil and palm touches are held weakly and read by phase, so a touch whose end never reached the watcher cannot leave the Pencil counted as down and every finger counted as a palm.
- **Not on Windows or Linux.** Touch radius and Pencil state are iPad concepts; the desktop port is unchanged.

### Straight marker lines and a canvas that stays fast on big notes (2026-11-03)

- **Marker lines straighten on lift.** `Ink.fittedLine` (core and `model.js`) fits the raw marker stroke to its principal axis. When the stroke spans at least `marker_straighten_length` (25 mm), no point is further from the axis than `marker_straighten_deviation` (12 %) of the span, and its path is at most `marker_straighten_detour` (1.3×) the span, it is committed as the segment from the first to the last point projected on the axis. The drawn angle is kept: no axis snap, because highlighting follows slanted text and PDF lines. Hold-to-straighten still works and wins when used.
- **Why big notes lagged while drawing.** Every element written to the journal got its own `fsync`, so erasing or moving 40 strokes flushed 40 times on the main thread. Every page change redrew the three full-screen ink layers, re-sorted every element several times per frame, and laid out and drew every text block even off screen. Every finished PDF page render redrew all the ink and re-rendered every View All thumbnail.
- **What changed.** `Journal.grouped` buffers the lines of one action and flushes once; each multi-element loop in `Library` runs inside it. `NotesStore.integrate` takes the page out of its dictionary before changing it, so the element array is not copied. The iPad canvas keeps a `RenderIndex` (live elements split into imports, markers and the rest, each with page-space bounds) rebuilt once per page change. A change redraws only the union of the bounds of the elements added, removed or updated (`setNeedsDisplay(_:)` on the element and marker layers). The renderer culls strokes and text against the visible rect, and stroke colours are cached. The eraser only tests strokes whose bounds meet the sweep. A PDF render refreshes the import layers only, thumbnails only refresh for their own asset, and new PDF resolutions are not requested until the camera has been still for 120 ms. The desktop port memoises the sorted live elements per elements array, draws the live marker and erase pieces on top of the page without copying it, culls text and prefilters the eraser by bounds.

### Memory budgets, a journal that stays small, and a note name that fits (2026-11-03)

- **Why the iPad ran out of memory.** Without GitHub sync the journal was never trimmed: every stroke, edit and rename since the first launch stayed in `journal.jsonl`, was decoded into memory at launch and replayed over the snapshot. Imported PDF renders were allowed 192 MB plus every opened `PDFDocument` forever, and white pages were darkened eagerly on light paper. Folder thumbnails and View All cells were rendered on the main thread with no cap, and undo history was kept for every note opened since launch.
- **Journal compaction.** `NotesStore.compactJournal(above:)` keeps one entry per notebook, page header and element: the last one, carrying the store's merged value when there were several, plus one page header at the page's earliest dropped slot so the page exists before its elements on replay. Sequences are kept, so a push that is in flight still settles the right entries. The journal format and the page schema are unchanged. The iPad compacts at launch, when a note closes and on a memory warning, above `memory.journal_compact_entries` (2000), never while a sync is running. The desktop writes page files directly and has no journal.
- **Budgets in `tokens.json` (`memory`).** PDF renders 96 MB, 3 open PDF documents, folder thumbnails 48 MB, a stroke path cache slack of 256 beyond twice the live elements, 500 text layouts, 200 undo steps per note. Both clients read them.
- **What is cleared when.** On a memory warning (iPad) every cache drops: PDF renders and documents, thumbnails, stroke paths, text layouts, off-screen PDF layers, and the undo history of every note but the open one. Closing a note drops its PDF renders and documents and its undo history; opening a note drops the folder thumbnails. The desktop does the same on closing a note, destroys pdf.js documents it evicts, and prunes its stroke path cache like the iPad.
- **Off the main thread.** Folder thumbnails and View All cells and strip pages render on a background queue (`Thumbnails`); the shared colour, text layout and baseline caches are locked for it. A PDF page is darkened when it is drawn inverted, not whenever it is white.
- **No retained canvas.** The glide and straighten display links target a weak `DisplayLinkTarget`, so a closed canvas is not kept alive by a running animation. Timers and links stop when the canvas leaves the window, and the desktop canvas cancels its frame requests on destroy.
- **The note name on the canvas.** It sits on a black rounded backdrop (`title.backdrop_opacity` 0.55, radius 10, padding 10 × 5) so it reads on white paper. It is never cut: it wraps to `title.lines` (2) and then shrinks down to `title.minimum_scale` (0.6) of its size, within the space left of the controls. The edit field used `.fixedSize()`, so a long name laid the top bar out wider than the screen, and every keystroke wrote the page header to the journal with an `fsync` and rebuilt the canvas render index. The field is now bounded and wraps the same way, and the name is saved once when editing ends. Folder names in the folder head are saved the same way.

### Synced groups (2026-11-02)

- **One file per group, membership on the member.** A group is `groups/<g_ id>.json` (`parent`, `title`, `kind`, `order`, plus the usual `updated`, `device`, `deleted`), and a notebook or page header carries the `group` it is in. Storing the members on the group would make two devices that each add a note to the same group overwrite each other; on the member, each addition is an edit of a different file. A group's title and order are last-writer-wins on its own file, and a tombstone wins, like a notebook. **Assumption:** the schema addition was agreed by the request to make groups sync; `schema_version` stays 1 because the fields are optional and old readers ignore them.
- **A member must match its group.** A member counts only while its group is live, of its kind, and in the member's own folder. Moving a folder or note clears its `group`; a member pointing at a deleted or foreign group reads as ungrouped, so nothing has to be rewritten when a group goes away.
- **Empty groups are removed.** Taking the last member out of a group (menu, drag out, move) tombstones the group, as the device-only groups dropped empty groups before.
- **Device groups move into the repository.** On launch, the iPad's `groups.<folder>` user defaults and the desktop's `groups.<folder>` local storage are read once, turned into synced groups for their live members, and deleted.
- **Local clocks only move forward.** `NotesStore.timestamp()` and the desktop `Library.timestamp()` return at least one millisecond after the last value they issued. Two edits of one record in the same millisecond (create a group, then take a member out at once) tied, and a tie kept the earlier copy.

### Windows and Linux parity with the iPad (2026-11-02)

The desktop app was behind since `f4c478b`. Each iPad pass is now ported; only the platform mappings are new.

- **The styled editor is a contenteditable.** `textEditor.js` keeps the editor model the iPad keeps in `NSTextStorage`: lines of runs, line prefixes visible and dimmed, inline marks hidden and shown as style. Every edit arrives as `beforeinput` and is applied to the model, which is serialised with the ported `RichText` (`richText.js`) and re-rendered; only IME composition is left to the browser and read back from the spans afterwards. Single-character deletes are computed from the caret, not from the browser's target range, which spanned the line break before a one-character line. `Ctrl+B`, `Ctrl+I` and `Ctrl+U` map to the `.md` toggles.
- **One parser per platform, same tests.** `markdown.js`, `richText.js` and `syntaxHighlighter.js` are line-by-line ports of `Markdown.swift`, `RichText.swift` and `SyntaxHighlighter.swift` (heading scales 2, 1.5, 1; underline tags; `{.language}` code spans; fence languages). The RichText test cases were run against the JavaScript port.
- **Text on the rows.** The renderer and the editor share `rowGap`, `rhythmFontSize`, `snappedTop` and `placedBox` in `renderer.js`, computed from Space Mono's canvas metrics. The baseline target is the unscaled ascender plus `(rows − 1)` rows, so a heading sits on the guide its last row ends on. Lines in the editor shift each span by the difference between that target and the browser's own baseline for its font. The font-size item, its slider and presets are gone; the text tool has no secondary nav.
- **Nav.** The secondary nav and the colour panel follow the main nav's edge offset; size presets lose their px captions; the size slider's track is an SVG cone; the secondary nav leaves as a capsule; pen and marker groups collapse with a sideways swipe judged at 22 px with 2× dominance and keep their state in local storage; tool glyphs carry their own tint and the eraser uses `eraser_ring`; holding the size slide shows the real size as a dot at the window centre; while carried, the nav turns when its frame touches a side or an end, with the 90 ms mutate leave. The nav layer now sits above the top bar, and the note title is no longer an obstacle, so the nav can lie over the name.
- **Folder screens.** Folders come before notes on every level. The folder head is a pill on its own `PillMotion` and shows only inside a folder. A drag computes, for every insertion index, the frame the dragged tile would get (the masonry for notes, the uniform grid for folders) and takes the slot under the pointer; the ghost no longer replays the tile entrance and lifts around the grabbed point. Tiles drop onto a group of their kind (outlined while targeted); cards of an open group drag out, show live in the grid while outside the group, and leave it on drop. A click on empty space and a sideways swipe that starts outside every open group close the open groups. The shut stack's name sits beside the stack again, cut from its left end as it opens.
- **Sheets.** Settings modules pop in and out on the `settings_pop` spring in a shuffled order with the `settings_stagger` step; settings no longer drop from the top and the backdrop goes at once. The icon and colour sheet has the wheel, saved colours (`folderPresets`) and a `+`, with wheel colours written 250 ms after the last move. Scrollbars are hidden everywhere.
- **Undo inside a text block, as on the iPad.** `textEditor.js` keeps its own history of the block's Markdown and selection: Ctrl+Z, Ctrl+Shift+Z and Ctrl+Y (and the context menu's Undo and Redo) step through it, typed characters within a second form one step, and any other edit is a step of its own. Code lines and inline code are excluded from the spell checker, as the iPad turns spell checking off in code.
- **A root grid laid out at zero width stayed collapsed.** The resize observer only re-laid the masonry, which the top level does not have; it now lays out the folder columns too.

### Notes as 1×1 tiles inside a folder (2026-11-03)

- **Every note is one tile.** The masonry sized a note by its page columns and rows, so a 4 × 4 note filled a quarter of the screen and a folder of big notes needed long scrolling. Every note now takes one slot of the masonry, whatever its extent; the `2×3` caption still tells its size. Drag slots are computed for single tiles, so a drop lands where the tiles make room.
- **The preview is the first page.** A tile draws cell (0, 0) only (`PageRenderer.cellThumbnail` on iPad, `renderCell` on Windows and Linux), not the whole note scaled down, which was both unreadable and the slowest part of opening a folder.
- **Cached within the thumbnail budget.** iPad previews go through `Thumbnails` (48 MB, off the main thread) as before. The desktop keeps its own previews in a least-recently-used map bounded by the same `memory.thumbnail_cache_megabytes`, cleared when a note opens like the iPad, and draws missing ones in idle time one after another (`requestIdleCallback`, a 16 ms timer where it is missing). A browser cannot draw on the canvas off the main thread without moving the renderer, the fonts and pdf.js into a worker, so idle slices are the desktop's equivalent. A preview of a note with PDF pages is keyed by an import revision that moves when a PDF page finishes rendering, so a preview drawn before its PDF was ready is not reused.
- **Names fit.** The name wraps to `title.tile_name_lines` (2) and then shrinks down to `title.tile_name_minimum_scale` (0.75) of 12 pt; past that it is cut with an ellipsis inside the tile. The header is two lines high on every tile, so all tiles have one height. The desktop estimates the scale from the overflow (area grows with the square of the size) before stepping down, which made fitting 41 names about six times cheaper than stepping from full size.
- **Desktop masonry positions.** `.tile-holder { position: relative }` came after `.masonry > * { position: absolute }` with the same specificity, so note tiles were laid out in flow and drifted down the page. `.masonry > .tile-holder` is absolute again. The import listener also re-rendered nothing, because it called `render` on the tile holder instead of its tile.
- **Measured.** Opening a folder of 41 notes in Chromium went from one 145 ms task to one of about 65 ms; what is left is building the tiles, with no preview drawn in that task.

### PDF pages beside View All (2026-11-03)

- **`source_name` on import elements.** An asset is named by its content hash, so nothing remembered which file a page came from. Import elements now carry an optional `source_name` (the file name at import), written by both clients; older clients ignore it, and PDFs imported before it show as "PDF 1", "PDF 2" in import order. It was asked for and approved as the one schema change.
- **One column per note's PDFs.** In View All, the far left lists every PDF the note has ever imported, grouped by asset in import order, including pages that were never placed or were removed (they come from the PDF itself, measured once per asset on the import queue). Each group takes an accent from `imports.accents`, which leaves out the green and red of the dots and the yellow of the selection. The column scrolls on its own and stays beside the notes column.

- **Tap, then tap.** A tapped PDF page is chosen (yellow outline); tapping a note page, in the grid or the strip, places it. `ImportPlacing.placed` in NotesCore (and `importPlacing` in `model.js`) decides the edit: a page already in the note is moved by whole cells, so its fit and scale stay; otherwise a new element is made at that cell; any other PDF page on the tapped cell is tombstoned. ### Carrying the nav: grabber, bubble, corner park, edge lock (2026-11-03, iPad, Windows and Linux)

One engine runs the whole move, `NavigationCarry` (`windows/src/modules/navigationCarry.js`) and `NavCarry` (`ios/VadosNotes/Navigation/NavCarry.swift`), line for line the same. It owns the position, the morph share (0 bar, 1 bubble) and their velocities, integrated per frame with springs, so every later step starts from where the last one is right now. A grab mid-flight, mid-dock or mid-park takes over that value and its velocity; nothing jumps. Every number is in `motion.carry` and the `morph`, `bubble_follow` and `dock` springs.

- **Grabber.** A 28 × 3 bar on the leading edge: the top edge when horizontal, the side facing the screen centre when vertical, with a hit area 14 pt beyond it. A drag starts on press, with no hold, and the bar follows from the grab point. The invisible end zones stay and now also carry on press. `navigation_grip_hold` is gone.
- **Clearing the stage.** From the grab until the bar lands, the secondary nav, the colour panel and the wheel leave with their normal leave and do not return. The top bar, undo/redo and the selection pill stay. **Assumption:** they are not toolbars that move with the nav, and hiding the whole chrome on every carry would flash the screen.
- **Morph.** The finger drives it (V/AS §14): free share = (finger travel − `morph_start` 120) / (`morph_full` 260 − 120), clamped. A finger faster than `throw_velocity` (1100 pt/s) latches it at 1 for the rest of the carry. Over an edge the target is 0, in a corner 1, in open space the free share. The share follows its target on the `morph` spring, and shape, size and content all read it: the shell lerps to a 56 pt circle, the bar's content fades out over the first half while it shrinks, and the bubble face (the selected tool's glyph) fades in over the second half. The grab offset shrinks with the morph so the bubble ends under the finger.
- **Bubble physics.** While carried, the bubble trails the finger on the `bubble_follow` spring (weighted by the morph, so the bar itself is 1:1) and stretches along its velocity (`stretch_per_velocity`, at most `stretch_limit`). On release faster than `throw_velocity`, or as a bubble in open space, it is thrown: the speed is capped at `throw_velocity_limit` (3200), decays by `throw_decay` per millisecond and bounces off the screen margin with `bounce` (0.4). Below `rest_velocity` it settles.
- **Corner park.** A finger inside `corner_zone` (140 pt) of two edges makes a bubble; released there it parks at the edge margin, avoiding the top bar. A thrown bubble that hits a wall inside a corner zone is caught there instead of bouncing, losing its speed into the wall so it does not overshoot the screen. A parked bubble keeps the stage cleared. A tap expands it along the nearer of its two edges (ties go to top or bottom); a drag past `tap_slop` carries it.
- **Edge lock.** The bar or bubble frame within `edge_zone` (40 pt) of one edge sets the orientation for that edge: vertical for left and right, horizontal for top and bottom; touching two edges keeps the current one. The dock is two phases. First the turn: a bar mutates (elements out on `navigation_mutate_leave`, shell turns over `navigation_switch × 2`); a bubble, whose content is hidden, turns at once and holds for `press` so the new size is measured. Only then does it travel to the edge margin on the `dock` spring while the morph goes to 0. A thrown bubble docks to the last wall it hit, or the nearest edge.
- **Return.** When the dock lands, the placement is saved and the secondary nav and panels enter again beside the bar's new position and orientation.
- **Saved placement** gains `corner` (`Preferences.navPlacement`, a device setting, not NotesCore or sync). A parked bubble comes back parked after a restart.
- **Edge hide stays for now.** It is a drag on the bar body, not on the grabber, so the gestures do not conflict, but corner parking does the same job (getting the bar out of the way). Proposed for removal; waiting for a yes.
- **Assumption:** all `motion.carry` values above, and the three springs (`morph` 0.28 / 0.8, `bubble_follow` 0.12 / 0.65, `dock` 0.36 / 0.82), were chosen on Windows with synthetic pointer input and have not been felt on an iPad.

### Carrying the nav, second pass: edges only, an even shrink, a springy unfold (2026-11-03, iPad, Windows and Linux)

The first iPad build was tried by hand. This pass replaces the bullets above where they disagree: the bubble face, the "Edge lock" zone, "A thrown bubble docks to the last wall it hit", the `press` hold, and the `dock` spring values.

- **Even shrink (iPad bug).** `PillShell` sized the shrinking capsule inside its `GeometryReader` without recentring it, so the bubble shrank into the bar's top-left corner. - **Shrink first, then gather.** The grab offset no longer fades with the morph from the start. It holds until the morph reaches `finger_centre_from` (0.35), then eases (smoothstep) to zero by the full bubble. The bar shrinks in place first, then the circle slides under the finger.

- **Edges only.** The toolbar rests against an edge or parks in a corner, never in open space. While carried, the finger inside `edge_share` (0.1) of the screen's width (left and right) or height (top and bottom) picks that edge and unfolds the bar towards it. Using the finger instead of the frame removes the feedback where an unfolding bar pulled itself in and out of the zone. A drop in open space docks to the nearest edge. Corners still win inside `corner_zone`.

- **The jump after landing (iPad bug).** The engine switched to idle, then called `onLand`, which saved the placement in a transaction without animation. SwiftUI applied the two in separate updates. In the first one the bar was placed from the old placement (where the drag began) with the placement spring on, so it jumped back that way and sprang home. `NavCarry` now calls `onLand` before it changes the state. - **The jump after landing, root cause (iPad bug).** Reordering did not fix it. The placement was a `@State` in `ToolNav` and the carry state lives in `NavCarry`. A `@State` write is queued with its transaction, while the view reads the object's state live, so SwiftUI could still draw a frame with the carry idle and the old placement, whatever order the writes ran in. The bar then sprang towards where the drag began, by a distance that grew with the drag, and snapped back when the queued placement arrived. The placement now lives in `NavCarry` (`placement`, set by `place`), so the state and the place the bar rests at are one source and every frame reads both as they are.

### Ink follows the camera as a picture, settings push the full screen, top bar order, View All zoom and edge removal (2026-11-03, iPad, Windows and Linux)

- **Why dense pages lagged.** Every pan, glide and pinch frame re-stroked every visible ink path on the CPU into three full-screen layers (`elementCanvas`, `markerCanvas`, `lineCanvas`). Handwriting is thousands of curve segments, and zoomed in each stroke covers more pixels and flattens into more segments, so the cost grew with zoom.
- **Fix (iPad).** `InkCanvasView` keeps a `rasterCamera`: the camera the three ink layers were last drawn with. ## 2026-11-04 — Tiled canvas rendering and a palm guard that lets go

- **Why moving around waited.** The iPad canvas drew its ink into three screen-sized views on the main thread. While panning or zooming those views were only stretched, so anything that scrolled into view stayed blank, and 0.12 s after the camera stopped the whole screen was redrawn at once. The paper and guides underneath were redrawn every frame of every gesture, and while a stroke was live the ink was too, which held the main thread and made touches lag.
- **Tiles.** `Canvas/CanvasTiles.swift` cuts the page into 256 pt tiles at power-of-two zoom levels. The level is `ceil(log2(scale) − 0.25)`, so a tile is shown between 0.59× and 1.19× of its drawn size. Each tile holds up to three images (guides and dividers, markers, other ink), drawn off the main thread on an `OperationQueue` from an immutable snapshot of the page. Camera moves only change the transform of three container layers, so pan and zoom cost no drawing. Visible tiles are drawn nearest the centre first, one ring of tiles around the screen is prefetched, and the whole page is always kept at the fitted zoom level as a fallback, so a fast pan or zoom shows that (soft) until the sharp tile lands instead of blank paper. A tile at another level is hidden once the current level covers its visible part, so ink is never drawn twice. Tiles with nothing in a pass keep no image. The cache is `memory.tile_cache_megabytes` (192 MB) and at most 1500 tiles; it evicts the levels furthest from the current one, then the tiles furthest from the screen centre, and keeps only the visible and fallback tiles on a memory warning.
- **Edits stay immediate.** A committed stroke, an erase or a move patches only the affected visible tiles synchronously: the old image is copied and the changed area is cleared and redrawn, clipped. Tiles off screen or at other levels are re-queued or dropped. A selection or lifted text being dragged is hidden from the tiles and drawn alone into a screen-sized overlay each frame. The paper itself is a shape layer.
- **Palm guard.** A touch is classified once, when first seen, and keeps that class until it lifts; only growing to a palm radius (52 pt) changes it later. The guard used to re-test every finger on every move, and its learned rest zone was the bounding box of up to 24 palm contacts plus 64 pt, which after a while covered most of the screen. Within 1.2 s of the Pencil's last contact any finger landing there was a palm, and a rejected touch fails the pan until every finger lifts, which read as the canvas being locked out after writing. Now: a finger landing while the Pencil is down is a palm; within 0.35 s of the Pencil lifting, so is one landing in the bottom fifth, in the right 30 % of the lower 45 %, or within 90 pt of one of the last 8 palm contacts of the past minute. Everything else is a finger at once.
- **Windows and Linux** already redraw the visible page every animation frame with no settle delay, and have no palm guard, so nothing was ported.

- **One picker.** `ColorTarget` (iPad) and the target keys `pen`, `marker`, `text-color`, `selection-color` (Windows) drive one `colourGroups` builder: the preset strip with hold-to-reorder and remove, the + button, collapsing, the variations pill and the wheel with the eyedropper. Only where the colour lands differs (`applyColor`: the tool, the open text block, or the selected elements).
- **Selection.** Colour in the selection menu now opens the shared colour sub nav beside the nav (key `selection-color`) instead of a menu of swatch chips; it recolours the selected elements on every pick and closes on the next canvas touch. Marker strokes in a selection take colours from the shared set too.
## 2026-11-05 — Text snapping (package E)

- **Toggle.** The text editor's nav gains Snap (glyph `snap`, accent when on) after Text colour. Tapping it while off turns snapping on and opens its secondary nav (`text-snap`); tapping it while that secondary nav is open turns snapping off; tapping it while snapping is on but another secondary nav is open brings the snap one back. Stored as `textSnapping` and `textSnapMode` (default `absolute`) on both platforms, so it survives relaunch.
- **Modes.** Absolute (`snap_absolute`) rounds the block's left edge to the 5 mm guide grid and its top to the row grid (`rowSpacing`). Relative (`snap_relative`) keeps the offset the block had when the drag began and moves it only in whole grid steps (`TextRhythm.snapped` / `snappedBox`). Rows were already snapped for text tops, so the two modes differ mainly in x.
- **Where it applies.** Moving the open block by its frame, and moving a lifted block with the text tool on the canvas. The side handles still resize freely.
- Windows' eraser modes and the snap modes now share one `modeGroup` builder for the two-button row with the sliding wash.
- New glyphs `snap`, `snap_absolute`, `snap_relative` in `shared/tokens.json`.
## 2026-11-05 — Explorer on the left, grab without a jump, Move opens the explorer (package F)

- **Left dock.** The explorer panel sits 12 pt from the left edge (plus the leading safe inset), slides in from the left on `explorer_enter` / out on `explorer_leave`, casts its shadow to the right, and its rows arrive from 24 pt to the left. This replaces the right-hand panel of 2026-11-04, and sits on the same side as the Explorer button, which now leads the top bar.
- **Create buttons.** New folder and New note are 36 pt circles (`folder_add`, `note_add`, create tint) in the header, left of ✕. The footer and its divider are gone; New note stays dimmed at the library root.
- **Grab without a jump.** The tile and row touch handlers reported the press point from when the hold began, but the drag only starts after the finger has travelled past the drag tolerance, so the ghost appeared offset by that travel and then snapped under the finger. `TileTouchView` (iPad) and `tileGestures` (Windows) now report the location at the moment the drag begins, and the grab offset is measured from the item's frame at that moment. The iPad explorer's ghost is now the row itself (its frame and size, scaled about the grab point) instead of a capsule centred on the finger. Windows' explorer already measured at drag start.
- **Move opens the explorer.** Move in a folder or note tile's menu opens the explorer in move mode (`Navigator.openExplorer(moving:)` / `Explorer.openMoving`), with every folder above the item expanded and the item's row scrolled to the centre. Move from the explorer's own menu scrolls to the row too. The old move sheet is no longer reached from the tiles; its code stays.
## 2026-11-05 — Session memory (package G)

- **Per-note view.** Each camera change records the note's zoom and the page point at the centre of the canvas (`SessionMemory` on iPad, `session.js` on Windows), not the raw offset, so the same place comes back on another window size or orientation. Writes are coalesced for 400 ms and flushed on route changes and when the app goes to the background / unloads. `fit()` restores the saved view instead of fitting when one exists, then constrains it to the page as usual. At most 300 notes are remembered; the least recently viewed are dropped. Device-local (UserDefaults / localStorage), not synced: it is a view, not note content, so the NotesCore schema is untouched.
- **Relaunch.** The current route is stored on every change (`lastRoute`). On launch, a stored note reopens (in its current folder, so a move since is followed) at its saved view, a stored folder reopens, and anything that no longer exists falls back to the library. Folder scroll positions are not restored.
